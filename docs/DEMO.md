# Что делать после запуска

## Открыть панель

1. Оставьте Docker Desktop работающим.
2. Откройте <http://localhost:8080>.
3. Войдите: логин `admin`, пароль — значение `ADMIN_PASSWORD` из файла `.env` в папке проекта. Кавычки и название параметра вводить не нужно.
4. Откройте демонстрационное задание. Если оно уже имеет архивы, повторная инициализация хранилища не нужна.

## Проверить копирование

1. Нажмите «Создать копию» и дождитесь завершения запроса.
2. Убедитесь, что появился новый архив, а в журнале операций есть успешная запись.
3. Выполните проверку архива кнопкой на странице задания.
4. Для восстановления выберите архив, введите `ВОССТАНОВИТЬ` и запустите операцию. Заменяются данные только отдельной тестовой БД `restore-db`.

Для независимой проверки откройте PowerShell в папке проекта и выполните:

```powershell
docker compose exec -T panel python manage.py smoke_backup
```

Ожидаемый результат начинается с `PASS`: архив создан, проверен и восстановлен; тестовые записи совпадают; исходная БД не изменена. Наличие архива без такого восстановления ещё не доказывает работоспособность копии.

## Проверить расписание

1. В настройках задания выберите «Каждые 5 минут» и включите автоматическое копирование.
2. Дождитесь ближайшей минуты, кратной пяти: например, 14:05, 14:10 или 14:15 по времени Europe/Moscow.
3. Обновите страницу задания. В «Журнале планировщика» должны появиться время запуска и `EXIT_CODE=0`.
4. Сравните имя последнего архива до и после запуска. Из-за политики хранения количество архивов за день может остаться прежним.

Браузер можно закрывать. Для запуска по расписанию компьютер и Docker Desktop должны продолжать работать.

## Какие скриншоты сохранить для отчёта

- Главная страница с включённым заданием.
- Настройки расписания и политики хранения.
- Список архивов и успешные ручные операции.
- Журнал планировщика с временем и `EXIT_CODE=0`.
- Вывод `docker compose ps`: пять работающих контейнеров.
- Результат `smoke_backup` с `PASS`.
- Содержимое таблицы `projects` в исходной и восстановленной БД.

Пароли и содержимое `.env` на скриншоты не включайте.

## Остановить и снова запустить

```powershell
docker compose stop
docker compose up -d --wait
```

Данные остаются в именованных томах. Не используйте `docker compose down -v`: параметр `-v` удаляет тома с БД и архивами.

Если `docker` не найден, используйте `powershell -ExecutionPolicy Bypass -File .\start.ps1 -NoBuild` для повторного запуска. Для изменения проекта и пересборки запускайте тот же скрипт без `-NoBuild`.

## Что ещё нужно для сдачи

Состояние проверок указано в `VERIFICATION.md`, оставшиеся этапы — в `PLAN.md`. Локальный Docker Compose, отчёт, многоузловое развёртывание и CI/CD — отдельные части работы. Успешный запуск панели не означает, что весь комплект для защиты уже готов.
