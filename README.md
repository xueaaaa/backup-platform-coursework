# Платформа резервного копирования PostgreSQL

Учебный проект по дисциплине «Настройка и администрирование сервисного программного обеспечения». Собственное приложение — только панель управления на Django. Создание дампа, архивирование, шифрование, дедупликацию, хранение и восстановление выполняют PostgreSQL, BorgBackup и borgmatic. Расписание выполняет системный cron.

Пошаговая инструкция после запуска: [docs/DEMO.md](docs/DEMO.md). Фактические результаты проверок: [docs/VERIFICATION.md](docs/VERIFICATION.md). В образах закреплены Borg 1.4.5 и borgmatic 1.9.14.

## Состав

| Контейнер | Роль |
|---|---|
| `panel` | Веб-панель, пользователи, права, CRUD заданий, адаптер команд borgmatic |
| `scheduler` | Готовый cron и borgmatic, выполнение опубликованных расписаний |
| `source-db` | PostgreSQL с демонстрационными данными |
| `restore-db` | Отдельная PostgreSQL для проверки восстановления |
| `proxy` | Nginx, HTTP и статические файлы |

`scheduler` не является самостоятельно написанным приложением. Его образ устанавливает готовые пакеты и небольшой shell-скрипт запуска команд. Для ручных действий те же Borg/borgmatic CLI доступны внутри контейнера панели. Docker socket не используется.

## Первый запуск

Нужны запущенный Docker Desktop в режиме Linux-контейнеров и Docker Compose v2. Команды выполняются из этой папки.

В Windows удобнее запустить `./start.ps1` из PowerShell. Скрипт найдёт Docker Desktop, создаст пароли, проверит конфигурацию и поднимет контейнеры. Python на хосте для этого варианта не нужен.

```powershell
python scripts/prepare_env.py
docker compose up --build -d --wait
```

Если Python не установлен, скопируйте `.env.example` в `.env` и замените все значения `replace-...` самостоятельно. Скрипт не изменяет существующий `.env`.

Откройте http://localhost:8080. Логин — `admin`, пароль — `ADMIN_PASSWORD` в локальном `.env`. Не публикуйте этот файл. После первого запуска изменение `ADMIN_PASSWORD` не меняет уже созданного пользователя: используйте `docker compose exec panel python manage.py changepassword admin`.

1. Откройте демонстрационное задание.
2. Нажмите «Инициализировать хранилище» один раз.
3. Нажмите «Создать копию» и проверьте появление архива.
4. В настройках выберите расписание и включите автоматическое копирование.
5. Для демонстрации используйте интервал пять минут; время расписания — Europe/Moscow.
6. Введите `ВОССТАНОВИТЬ` в форме восстановления. Восстановление заменяет данные только на `restore-db`.

Расписание работает независимо от открытого браузера и веб-процессов. Ручные операции выполняются синхронно, до трёх минут. Блокировка `flock` защищает задание от одновременного ручного и автоматического запуска, Borg дополнительно блокирует репозиторий.

## Проверка результата

```powershell
docker compose exec -T panel python manage.py smoke_backup
```

Эта команда использует настоящие утилиты, создаёт зашифрованный архив, проверяет его, восстанавливает в тестовую БД и сравнивает содержимое демонстрационной таблицы `projects`. Исходная БД не изменяется. Проверка рассчитана на учебную схему из `infra/seed.sql`, а не на произвольную производственную БД.

Проверить записи вручную:

```powershell
docker compose exec source-db psql -U backup -d coursework -c 'TABLE projects;'
docker compose exec restore-db psql -U backup -d coursework -c 'TABLE projects;'
```

Проверить команду планировщика без ожидания следующей минуты:

```powershell
docker compose exec scheduler /usr/local/bin/run-backup 1
```

`1` — идентификатор первого задания. Такая команда проверяет wrapper, но сама по себе не подтверждает срабатывание cron по времени. Для этого включите расписание и дождитесь записи в «Журнале планировщика».

## Пользователи и права

Управление пользователями доступно администратору по `/admin/`.

- «Наблюдатели»: просмотр заданий и результатов.
- «Операторы»: CRUD заданий, создание и проверка копий; без права восстановления.
- Администратор: все действия, включая восстановление и назначение прав.

Встроенный административный интерфейс служит для управления пользователями. Настройки заданий изменяйте через собственную панель: только она синхронизирует изменения с YAML и cron.

## Постоянные данные

Именованные тома Docker сохраняют исходную БД, тестовую БД, настройки панели, архивы, ключевые метаданные Borg, конфигурации и журналы. Обычный `docker compose down` их не удаляет. Удаление задания в панели отключает расписание, удаляет его настройки, но сохраняет репозиторий и журнал на диске.

Для чтения оставшегося репозитория после удаления задания:

```powershell
docker compose exec panel borg list /repository/plan-1
```

Сохраните `BORG_PASSPHRASE` вне стенда. Экспортируйте ключ репозитория и храните отдельно от резервных копий:

```powershell
docker compose exec panel borg key export /repository/plan-1 /state/plan-1.key
docker compose cp panel:/state/plan-1.key ./plan-1.key
```

Экспортированный ключ — секрет; не добавляйте его в репозиторий Git. Репозиторий с `repokey` уже содержит зашифрованный ключ, отдельный экспорт нужен для аварийного восстановления ключевого материала.

## Структура

```text
config/                  настройки Django и маршруты
console/                 единственное собственное приложение — панель
  engine.py              адаптер готовых команд и генерация YAML/cron
  management/commands/   настройка ролей и интеграционная проверка
templates/               собственный интерфейс
infra/                   Nginx, тестовые данные и запуск готовых утилит
scripts/                 подготовка локальных секретов
docs/                    архитектура, требования и ход работы
compose.yaml             локальный стенд из пяти контейнеров
Dockerfile               образы готового движка и панели
.github/workflows/ci.yml  тесты, сборка, запуск и проверка восстановления
```

## Разработка и проверки

Python 3.12:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py check
python manage.py test
python manage.py makemigrations --check --dry-run
```

Тесты используют временные каталоги и БД; команды Borg подменяются только в модульных тестах. Совместимость YAML и CLI проверяется по установленному borgmatic 1.9.14. Реальное копирование проверяет отдельная команда `smoke_backup` внутри Docker.

Workflow предполагает, что именно эта папка станет корнем Git-репозитория. Сейчас публикация на GitHub и выполнение удалённого workflow не подтверждены.

## Границы первого этапа

Это локальный учебный стенд для одной заранее определённой БД. Он ещё не означает выполнение требований о многоузловом кластере, облачном развёртывании и CD. Их состояние и следующие шаги перечислены в `docs/PLAN.md`.

Архивы хранятся на том же Docker-хосте: потеря хоста может уничтожить и оригиналы, и копии. Для завершённой схемы защиты потребуется независимое место хранения. Метаданные самой панели пока не включаются в копию PostgreSQL. Наличие двух серверов БД в Compose не является кластером Swarm.
